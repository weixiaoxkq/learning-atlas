# Dense、MoE、Router 与激活参数

> 从已有聊天提炼的学习笔记；已讲解不等于已掌握。

## 核心概念

Dense 层让 Token 执行同一套 FFN。稀疏 MoE 层准备多套 Expert FFN，由 Router 根据当前 Token 表示选择少量专家，按路由权重合并输出。

```text
Token 表示 → Router → 所选 Expert FFN → 加权组合
```

这不是多个独立聊天机器人讨论，也不等于 Multi-Agent。Expert 的偏好通常由训练形成，不能直接指定为“数学专家、编程专家”。

## 总参数与激活参数

16 个专家、每个 100M、每 Token 选择 2 个：专家总参数为 1.6B，每 Token 激活的专家参数为 200M。还需另计 Attention、Router 等共享部分。

若全部专家常驻设备，权重存储仍要容纳全部专家；激活专家较少不表示整个模型的权重显存同样缩小。

## 工程问题

路由负载不均衡、专家间通信和调度都会影响效率。MoE 与 Dense 不构成无条件的优劣排序；输入信息流架构与专家稀疏性也是两个独立维度。

## 本次补充：路由和逐 Token 计算

在典型 MoE Transformer 层中，Attention 之后的 Token 表示交给 Router，选择少量 Expert FFN，按路由权重汇总输出，再继续后续层。Router 根据当前上下文表示工作，不是按 Token 字面查固定专家词典；同一个 Token 在不同上下文或不同 MoE 层可以选择不同专家。

若某一层有 8 个专家、每个 1 亿参数、每 Token 选 2 个，则该层专家总量为 8 亿，每 Token 激活的专家参数为 2 亿；共享参数另计。一批 Token 可能选择不同专家，合计用到更多甚至全部专家。

激活参数比例不直接等于显存比例或速度比例。全部专家常驻时仍须存储全部权重，还存在 Attention、Router、数据搬运、通信和调度开销。
